02 · EngineImpl

The transaction pipeline

Every batch — even one spanning several tables — becomes exactly one all-or-nothing transaction.

flowchart TB
 A["apply(batch)"] --> FP["fingerprint batch content
outside the lock"]
 FP --> L{{"fair mutex — one batch decides at a time"}}
 L --> D{"load_id seen
before?"}
 D -- "never" --> T["txn = nextTxn
monotonic, crash-recovered"]
 D -- "same content" --> R1["return ORIGINAL receipt
apply nothing (safe retry)"]
 D -- "different content" --> R2["REFUSE loudly
apply nothing"]
 T --> P["Scd2Applier per table"]
 P --> W["ONE WAL record:
all mutations + audit manifest"]
 W --> S["write hot store · nextTxn++"]
 S --> F["wait for fsync OUTSIDE mutex
callers share one group commit"]
 F --> M["receipt: manifest with exact counts"]

05 · WAL

Group commit — how 50 users share one disk flush

sequenceDiagram
 participant U1 as user A
 participant U2 as user B
 participant U3 as user C
 participant W as WAL writer
 participant D as disk
 U1->>W: txn 41 appended
 U2->>W: txn 42 appended
 U3->>W: txn 43 appended
 Note over W: collect up to 2 ms / 512 txns
 W->>D: ONE fsync covers 41+42+43
 D-->>W: durable
 W-->>U1: acknowledged
 W-->>U2: acknowledged
 W-->>U3: acknowledged
Recovery contract: torn tail after a crash → truncated cleanly; corruption in the middle → fail loudly, never skip. Nothing is ever acknowledged before its bytes are durable.
